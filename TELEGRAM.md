# Telegram alerts

Open **Radar, đồng đội & Telegram**, then **Cảnh báo Telegram** below the map. The replay service evaluates new snapshots in the background, including while the browser is closed.

1. Create your bot with [@BotFather](https://t.me/BotFather) and copy its Bot Token.
2. Open your bot in Telegram and send `/start`. For a group, add the bot and allow it to send messages there.
3. Obtain the chat's numeric ID from your bot's [getUpdates](https://core.telegram.org/bots/api#getupdates) response (`message.chat.id`), or use a chat ID you already know. Enter the Bot Token and Chat ID in the local radar form.
4. Select your own SteamID in **Radar của bạn**. Set a **1,000 m** radius and **10%** larger threshold. The independent low-HP rule defaults to target current HP **below 50% of your current HP**. Each rule can be enabled separately. Optionally copy your teammates into the server's ignore list.
5. Save the settings, use **Gửi tin thử**, then enable alerts and save. A blank token field preserves the saved token. Untick the enable checkbox and save to stop notifications.

Tokens are stored only in the selected local data directory's `telegram.json`, omitted from API responses and release packages. A test message or alert uses Telegram's official [sendMessage](https://core.telegram.org/bots/api#sendmessage) endpoint. As selected by the user, alerts now include the condition met, species, growth, distance, compass direction/bearing, estimated relative size, HP, stamina and observation ages. Optional X/Y coordinates are disabled by default and can be enabled in the form. Player names, SteamIDs and replay filenames are omitted. The bot uses plain text, and messages stay below 4,000 characters. If all complete descriptions don't fit, only included targets are marked delivered; the rest remain eligible at the next new snapshot.

**Larger is an estimate from maximum HP**, matching the radar's existing weight estimate; it is not a verified mass field. The target must be strictly heavier than you and at least 1.10 times your estimate. Growth percentage alone is not used. Only dinosaurs with observed positive maximum HP, valid coordinates, and an active, non-dead actor qualify. Unknown mass, animals/fish without a verified weight estimate, your own character, and ignored SteamIDs are excluded. The latest actor for each SteamID wins before filtering, avoiding stale respawn actors.

**Low HP compares current absolute HP, not each dinosaur's HP percentage or maximum HP.** If you currently have 1,000 HP, the default rule alerts on a living dinosaur with fewer than 500 HP. Exactly 500 does not meet the strict "below 50%" rule. The target does not need to be larger; this rule also works when maximum HP/weight is unavailable. Missing or invalid current HP never substitutes zero or a guessed maximum. Both your dinosaur and the target must be alive and in scope with valid positions; self and ignored teammates are excluded from both rules.

Each displayed vital uses observed values only. Missing HP, stamina, growth or relative size appears as **chưa rõ**. Position, HP and stamina ages are measured relative to the last replay frame; the source file's wall-clock age is displayed separately. The viewer cannot infer an exact live position from file modification time.

**Target Blood uses your current Blood as the denominator**, matching the user's correction. With the default 1,000 m radius and 50% threshold, target current Blood must be strictly less than half your current Blood. For example, you have 1,000 Blood and a target has 499: alert. Exactly 500 does not alert. The target's own maximum Blood and your maximum Blood are not used for this trigger. Both current observations must exist and your current Blood must be positive. This condition is independent of HP and size and is enabled by default; your own low-Blood warning remains off. The optional own-Blood warning uses your current/maximum Blood and can be enabled separately. Notifications include Blood values and the target's relative Blood percentage. Matching observed nonzero GroupIds are treated as teammates, alongside ignored SteamIDs.

When upgrading from the briefly used target-maximum-Blood comparison, only the target-Blood encounter state is reset; delivered size and HP encounters remain deduplicated.

An encounter alerts on first detection, then on closer distance bands: 1,000 / 500 / 250 m with the default radius. Boundary jitter cannot repeat an already reported band. Leaving and re-entering needs at least 120 seconds since the last alert of the same kind. Size and low-HP conditions have independent encounter state: a newly met low-HP condition can alert even after the size condition was already reported. Encounter state persists across service restarts, and old delivered size encounters are migrated on upgrade. Several new conditions on the same target are grouped in one description. Network failures don't stop decoding, aren't counted as delivered, and retry on a new snapshot after backoff; Telegram rate limits honor `retry_after`.

Replay scans default to **20 seconds** and can be changed in **Nguồn replay** (5–3,600 seconds). This is a scan interval, not a guaranteed alert latency: the game must write the data, and the copy/decode must finish. Stale source files older than 90 seconds pause Telegram alerts. No alert is generated by seeking the browser timeline or opening an archived snapshot.

Validation: `python -m unittest discover -s tests -p test_telegram.py` exercises exact thresholds, independent low-HP and size rules, current-vs-maximum HP, position units, death/scope/missing data, deduplication, closer bands, encounter migration, restart persistence, cooldown, rich messages, optional coordinates, message length and delivery accounting, HTTP configuration, token redaction and rate limits. The transport is mocked; these tests send no Telegram messages.
